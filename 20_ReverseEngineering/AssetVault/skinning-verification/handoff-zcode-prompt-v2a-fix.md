# 交给 zcode 的提示词:V2a 倒立 bug 修复确认 + 朝向断言(用户粘贴用)

---
## 背景(必读)

上一轮 V2a 几何组装已通过 DSH 全量验收,但**用户实看渲染图发现角色倒立**。DSH 已定位并修复该 bug,你的任务:核对修复 → 重跑组装 → 加防复发断言 → 重新验收 → 更新文档与记忆。

**真 bug:站立旋转符号错了(已由 DSH 修复)。**
- 根因:manifest 的 `standRotationEuler` 用了 `[-90,0,0]`(照搬淘宝 FBX 管线的 `rot(-90,0,0)` 惯例),但本管线存在 S·C 顶点镜像,导入后头部在 **−Z**;`Rx(−90°)` 把 −Z 转到 **−Y(头朝下)**。正立需要 **`Rx(+90°)`**。
- 数学链(全有实测数字):作者空间 Head z=+1.417 → GLB 写入 S 镜像(z=−1.417)→ UnityGLTF 导入 C 镜像 → 导入后 Head z=−1.417;`Rx(−90)` 使 Head y=−1.417(头在下,旧渲染即如此),`Rx(+90)` 使 Head y=+1.417(头在上)。
- DSH 已把 `Assets\SourceAssets\Skeleton\v2a_assembly_manifest.json` 的 `"standRotationEuler"` 从 `[-90.0,0.0,0.0]` 改为 `[90.0,0.0,0.0]`。**不要改回去。**
- 为什么上一轮程序化验收没抓到:蒙皮恒等、AABB 对照、覆盖率、连通域全是**旋转不变量**,倒立人形照常 27/27 PASS。教训:朝向类问题必须人眼或朝向断言。

**非 bug:颜色与游戏不同,不需要任何动作。**
- V2a 禁碰材质,渲染用 UnityGLTF 默认 PBRGraph(灰、无贴图),V1 同套;游戏多彩观感是 V2b(HoyoToon + 115 张贴图)的交付物。
- 四张图明暗不同是因为**灯光跟随相机旋转**(每视角顺光、默认材质无环境光补偿)。可选改进:V2a 展示渲染把灯光固定不随相机转,四视角观感更可比;不改也不影响验收。

## 任务清单(按顺序执行)

1. **核对修复**:
   - 读 manifest 确认 `standRotationEuler = [90, 0, 0]`;
   - grep `tools\` 与 `Assets\` 确认没有其他地方硬编码 `-90` 的站立旋转;
   - 对照 `skinning-math-derivation.md` §5-6 复核上述数学链。
2. **重跑组装**:Unity 编辑器执行 **Remielle → V2a Assembly Geometry**(或等效批处理),重新生成 prefab、四视角渲染、`v2a_report.json`、`v2a_silhouette.json`。
3. **加朝向断言(DSH 建议,防复发)**:在 `V2aAssembly.cs` 骨架构建完成后、渲染前加入:
   - 断言 `Head 世界 y > Pelvis 世界 y`,不满足则 `LogError` 并中止;
   - 在日志与报告里输出 Head/Pelvis 世界坐标作为朝向验收字段。
4. **重新验收(全部程序化)**:
   - 27/27 maxDev 与 aabbErr 仍应为 ≤1e-6 量级(修复不影响蒙皮恒等);
   - 剪影覆盖率/最大连通域与上次同量级(正面 ~9.5% / ~95%);
   - 朝向断言 PASS;总 bounds 预期 y 范围 ≈ **[−0.51, +1.62]**(旧版 [−1.62, +0.51] 的镜像),Head 在 y≈+1.417;
   - 正面(posZ)视图为面部朝向。
5. **产物核对**:prefab 在编辑器打开即正立;四视角渲染头部朝上。
6. **更新文档与记忆**:
   - `PROGRESS.md`:记录倒立 bug 根因(站姿旋转符号 × S·C 镜像链)、修复、朝向断言;
   - zcode 项目记忆(zzz 项目):补一条坑——"本 GLB 管线导入后角色头部在 −Z,站立表现层旋转必须 `Rx(+90°)`;淘宝 FBX 的 `rot(-90,0,0)` 惯例不适用(该管线无 S·C 顶点镜像)"。

## 约束

- 不要重新推导蒙皮数学(已定案,权威文档在 `RemielleAssetVault\skinning-verification\`)。
